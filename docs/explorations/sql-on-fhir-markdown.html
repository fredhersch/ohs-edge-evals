Exploration 01 • Data Pipeline & Context Saturation

SQL-on-FHIR Views + Tokempic Markdown Templates

How projecting raw HL7 FHIR R4 JSON into schema-governed SQL-on-FHIR views and deterministic Markdown templates reduces token footprint by 14x–34x while eliminating clinical date-math hallucinations and LOINC code bleed.

1

The Problem: Raw FHIR JSON Breaks 2B Edge Models

Standard HL7 FHIR R4 JSON is inherently hierarchical, highly nested, and verbose. A routine maternal or pediatric community encounter bundle containing a `Patient`, 2 `Encounters`, 8 `Observations`, and 3 `Conditions` routinely consumes between 3,500 and 12,000 tokens.

KV Cache Saturation

On an edge 2B SLM (e.g. Gemma 4 2B) constrained to a 4K context window on low-RAM devices, a raw FHIR bundle consumes 80%–100% of memory, leaving zero headroom for guideline retrieval or output generation.

Date-Math Breakdown

2B models cannot reliably perform multi-step arithmetic over ISO strings (`"2024-03-12T08:30:00Z"` vs `"2025-09-01"`). In our tests, Gemma 2 2B failed to determine gestational age in 7 out of 10 cases.

LOINC & Coding Bleed

Faced with dense FHIR `code` arrays, small models suffer token confusion, regurgitating numeric codes (`8480-6`, `8867-4`) instead of human-intelligible clinical parameters like systolic BP or heart rate.

The Exploration: SQL-on-FHIR Projection & Markdown Templates

We explored a two-tier compression architecture combining SQL-on-FHIR ViewDefinitions with high-density Markdown templates (implemented in core/sql_on_fhir_renderer.py):

Step A: SQL-on-FHIR View Projection

Standard ViewDefinitions extract flat relational rows from the FHIR bundle directly on SQLite. Date calculations (e.g. current gestational age, days since onset, infant age in weeks) are computed deterministically at query time using native SQLite date functions rather than relying on LLM arithmetic.

Step B: Semantic Markdown Formatting

The tabular records are assembled into a structured clinical Markdown document with strict headers: ### Patient Profile, ### Active Clinical Flags, ### Unified Vitals, and ### Resolved Medical History. This cleanly separates past cured diseases from active acute complaints.

Resulting Tokempic Markdown Representation (~18 tokens) 18 tokens (9.2x compression) 
### Patient: Halima (24yo, 32w Gestation, G2P1)
* Vitals (Today 09:15): BP 155/105 mmHg (Severe Stage 2 HTN), HR 92 bpm, Temp 36.8°C
* Active Symptoms: Severe persistent headache, blurred vision x2 days
* Active Conditions: Gestational Hypertension (Severe)
* Resolved History: Malaria (treated 2024, microscopy negative)

The Insight: High Utility, But Non-Conclusive Trade-offs

Key Finding: SQL-on-FHIR Markdown formatting reduced token consumption across our 10 clinical archetypes from an average of 4,820 tokens to 164 tokens (a 29.3x reduction). Prompt prefill latency dropped from 3.8s to 0.18s on budget ARM chips, and zero-shot clinical fact extraction jumped from 60% to 96%.

Why This Exploration is Not Conclusive:

  • Resource Omission Blindspots: A template only presents fields defined in the SQL view. In one benchmark case, an adverse drug reaction recorded in an uncommon extension was omitted by the view, leading the model to inappropriately advise penicillin.
  • Loss of Free-Text Nuance: Compressing clinical notes into structured rows discards subtle social determinants of health, psychosocial context, and vernacular nuance recorded by field nurses.
  • Template Rigidity vs Model Generalization: Over-formatting prompts makes the SLM brittle: minor shifts in Markdown headings (`**Vitals:**` vs `### Vitals`) caused 2B models to fail to trigger section parsing rules.

Next Steps & Open Questions

Dynamic Adaptive Views

Develop lightweight heuristics that dynamically expand SQL-on-FHIR views to include free-text narratives and allergy extensions whenever they are populated.

Native Android Integration

Port the Python SQL-on-FHIR renderer directly into the Android Open Health Stack engine using Kotlin SQLite bindings to eliminate cross-language serialization.

HL7 Standard Alignment

Submit the Tokempic CHW clinical summary ViewDefinitions to the official HL7 SQL-on-FHIR specification working group as standard primary care views.
