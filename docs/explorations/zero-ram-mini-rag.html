Exploration 02 • Retrieval & Memory Efficiency

Zero-RAM Protocol Mini-RAG & Swahili Vernacular Retrieval

Why standard dense vector databases trigger Android Low Memory Killer crashes on 3GB budget phones, and how embedded SQLite FTS5 with vernacular synonym expansion delivers sub-12ms guideline retrieval at zero memory cost.

1

The Problem: Vector Embeddings Starve Frontline Devices

Standard cloud RAG stacks assume abundant RAM for continuous vector embeddings (e.g. BGE-small, MedGemma-embed, FAISS index). On a typical frontline device (e.g. Tecno Spark 10 or Samsung Galaxy A04 running Android Go with 3GB–4GB RAM), the operating environment is severely constrained:

Android LMK Killing

Loading an embedding model (120MB–350MB) alongside the quantized 2B SLM (1.4GB–2.0GB) and Android OS processes pushes memory beyond the kernel threshold, causing the Low Memory Killer to abruptly crash the CHW app.

Vernacular Vocabulary Gap

Generic dense vector models are trained on Western academic literature and fail to map colloquial East African health vernacular (e.g. Swahili degedege for febrile seizure, kuharisha for acute watery diarrhea).

Multi-Step Pipeline Latency

Executing a neural embedding forward pass before initiating SLM prompt prefill adds 1.8s–3.5s of compute delay on budget quad-core MediaTek processors, severely degrading the CHW experience.

2

The Exploration: SQLite FTS5 + Deterministic Query Synthesis

Instead of running neural vector models, we leveraged the native SQLite FTS5 (Full-Text Search) engine already present in the Android SQLite runtime, paired with a curated Swahili Vernacular Synonym Trigger Map (implemented in chw-edge-evals/core/acdu_retriever.py):

Zero Additional RAM Footprint

FTS5 indexes are stored directly within the local app database file (e.g. `cdu_registry.db`). Queries execute in C-level memory space with 0 MB persistent background RAM allocated to embedding tensors.

Swahili Trigger Expansion

When clinical flags (e.g. fever + convulsion) or CHW notes enter the pipeline, the retriever expands search terms with bilingual vernacular synonyms: ("convulsion" OR "seizure" OR "degedege" OR "kifafa").

FTS5 BM25 SQL Execution Execution Time: 7.2 ms 
SELECT cdu_id, title, content, bm25(cdu_fts) as score
FROM cdu_fts 
WHERE cdu_fts MATCH '("convulsion" OR "degedege") AND ("fever" OR "homa")'
ORDER BY score ASC 
LIMIT 2;
3

The Insight: Fast & Reliable, But Lacks Semantic Fuzziness

Key Finding: In benchmark testing across 30 Kenya eCHIS encounters, SQLite FTS5 achieved 100% protocol recall on Swahili vernacular inquiries while taking only 6ms to 12ms per retrieval. It saved 280MB of device RAM compared to MedGemma embedding models.

Why This Exploration is Not Conclusive:

  • Vocabulary Fragility: If a health worker introduces an unindexed idiom (e.g. Sheng slang or localized Luo/Kikuyu borrowings), keyword BM25 fails completely and returns zero documents.
  • Context Clutter in Multi-Morbidity: Without dense reranking, BM25 can retrieve multiple protocols for overlapping symptoms (e.g. fever returning Malaria, Pneumonia, and Sepsis simultaneously), crowding the SLM's token budget.

Next Steps & Open Questions

Hybrid Sparse-Dense Evaluator

Evaluate micro-embeddings (INT8 quantized under 15M parameters via LiteRT) running on demand only when FTS5 confidence drops below a threshold.

Multi-Locale Vernacular Thesaurus

Collaborate with frontline partners (e.g. PATH Kenya, HelpMum Nigeria) to formalize regional clinical glossaries for automatic FTS expansion.

Pre-Retrieval FHIRPath Gating

Use deterministic FHIRPath expressions on the patient bundle to filter the searchable FTS5 candidate space by age, sex, and pregnancy status before keyword scoring.
