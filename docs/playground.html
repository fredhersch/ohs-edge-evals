Atomic Clinical Decision Units (aCDU) & Tokempic

Decoupled edge architecture: deterministic rule evaluation (FHIRPath), compressed patient context (Tokempic SQL-on-FHIR), and safe language synthesis. For the comprehensive evaluation and background, see the Architecture Story →

1. Decision Logic 100% Deterministic
FHIRPath & PlanDefinition

Evaluates structured criteria (BP ≥ 140/90) directly on patient FHIR observations. Returns the exact aCDU code.

• Decides WHAT to do (0% LLM)
2. Context Compression 100% Deterministic
Tokempic (SQL-on-FHIR)

Pre-computes age (16m, 32wks), normalizes vitals (148/96 mmHg), and compresses verbose bundles into ~320 tokens.

• Provides WHO & WHAT happened
3. Frontline Briefing Constrained SLM + Gate
Edge SLM & Regex Verifier

Gemma 2B weaves patient facts with aCDU guardrails into an empathetic 3-bullet CHW script (≤ 120 words). Deterministic Regex Gate verifies zero forbidden tokens escaped.

• Generates HOW to communicate safely
Why Tokempic? Solving 3 Edge SLM Failure Modes
1. Zero Date-Math Errors: 2B models cannot reliably calculate age from birth dates (confusing infants for adults). Tokempic calculates relative ages deterministically.
2. Zero LOINC Code Bleed: Prevents raw technical identifiers (8480-6) from corrupting vitals; emits clean clinical strings (148/96 mmHg).
3. 90% Context Free: Compresses raw FHIR JSON from >1,000 to ~320 tokens, preserving 90% of device RAM for clinical guidelines and prompt rules.
