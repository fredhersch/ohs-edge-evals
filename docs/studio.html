          Edge SLM Fine-Tuning Execution Pipeline
        

        

          Follow these 3 steps to take your exported clinical preference dataset and fine-tune Gemma 2 2B or Llama 3.2 3B using Direct Preference Optimization (DPO) and QLoRA.
        


        

          

            
Step 1: Inspect & Validate Exported DPO Dataset

            
Check the generated pairs in chw-edge-evals/dataset/dpo_preference_data.jsonl:

            
python3 fine_tune_slm_dpo.py --dataset chw-edge-evals/dataset/dpo_preference_data.jsonl --dry-run

          


          

            
Step 2: Run DPO QLoRA Fine-Tuning

            
Train the LoRA adapter with Hugging Face TRL on GPU or Mac MPS:

            
python3 fine_tune_slm_dpo.py   --dataset chw-edge-evals/dataset/dpo_preference_data.jsonl   --model-id google/gemma-2-2b-it   --output-dir ./gemma2_chw_dpo_adapter   --epochs 3 --lr 5e-6 --beta 0.1

          


          

            
Step 3: Convert to GGUF and Register in Ollama

            
Merge weights, quantize to INT4/INT8 GGUF, and verify in the Visual Runner:

            
# Merge adapter and export to GGUF
python3 llama.cpp/convert_hf_to_gguf.py ./merged_model --outfile ./gemma2-2b-chw-dpo.gguf --outtype q8_0

# Create Ollama model
ollama create gemma2:2b-chw-dpo -f Modelfile.dpo

# Re-run benchmark to verify pass-rate improvements
python3 chw-edge-evals/run_evals.py --model gemma2:2b-chw-dpo
